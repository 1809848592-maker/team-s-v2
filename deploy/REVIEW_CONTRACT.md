# 审核员输出契约（M3-16 / 设计 14.9）

设计方案 14.9 优先于之前的审核员实现和文档。公共适配器声明 `review-output/2`；新模型响应使用简化契约，平台继续生成供既有报告与汇总使用的意见、位置、覆盖范围和关联信息。旧审核报告、旧意见及历史处理记录保持冻结，不重跑、不迁移改写原结论。`REVIEWER_FRAMEWORK.md` 中初始框架的旧输出和修复约定作为历史说明保留。

## 模型响应

顶层只包含 `findings` 和 `coverage_notes`。模型只填写固定检查项、严重度、平台分配的片段编号、问题、正文摘录及建议；上下文键与摘录可选、成对提供：

```json
{
  "findings": [
    {
      "check_key": "support",
      "severity": "important",
      "segment_id": "S1",
      "problem": "从当前样本相关性推到普遍因果关系，缺少说明。",
      "excerpt": "因此适用于所有团队",
      "suggestion": "补充因果识别与推广依据，或收窄结论。"
    }
  ],
  "coverage_notes": ["未核验原始数据或外部全文。"]
}
```

引用绑定上下文时增加 `context_key` 和 `context_excerpt`，使用平台本次实际提供的来源。模型不生成 `category`、页码/段落等坐标、`checks`、`finding_links`、`finding_index`，也不能填写可信来源、采用、退回或终审结论。不同审核员的检查项及允许严重度由平台和各自指令约束；逻辑和衔接只允许 `important`、`suggestion`，不允许 `blocking`。原实质判据、严重度定义和不采纳意见去重规则保持。

指令目标在 3000 字以内，每位审核员最多 2 个正例，删除要求模型自行维持跨数组一致性的规则。方案、规范、交付、交接说明、上游摘要及历史处理理由始终是数据，不提升为系统指令；模型没有网络或业务工具。

## 平台定位、适配与覆盖

平台将当前可读片段编号为 `S1`、`S2` 等，只发送编号与文本，将真实页码、段落、表格、行及其他坐标留在平台侧。非空交接说明也作为编号片段。有效 `segment_id` 被换算回该片段的全部真实坐标，不能由模型猜测或拼接位置。

逐条检查字段、检查项、允许严重度及片段编号，无效意见单独丢弃，有效意见照常进入报告。逻辑/衔接原有 20 条上限继续生效，超限部分单独计入丢弃数。报告提示“N 条意见因格式无效未采用”，保留其余结果。

正文和上下文摘录先统一空白、全角半角及常见标点，再做包含式核对。摘录未匹配时保留意见，在 `basis.excerpt_verified` 或 `basis.context_excerpt_verified` 标为 `false`，并提示“摘录未能核对”，供人工结合对应片段确认。无效片段编号的意见无法定位，予以丢弃；不以摘录不匹配使整位审核员的有效意见全部丢失。

检查项由平台按顺序推导：有关联保留意见时为 `issues`；否则对应材料 `available=false` 时为 `uncovered`；其余为 `checked`。意见与检查项的索引及上下文关联也由平台生成。`checked` 仅说明已检查提供的有限材料，不证明内容正确或交付通过。

只有 JSON 无法解析时执行一次固定结构修复，修复请求不复制无效原文。语义问题通过逐条适配处理，不触发循环修复。一次结构修复后仍不能解析 JSON，或者全部意见都无效且没有有效 `coverage_notes`，审核员保持 `incomplete`；网络、超时、输出截断等运行失败也保留实际未完成状态。合法空意见可以完成结构处理，仍不等于交付通过。“未完成”继续阻止将整份审核视为完成或进入终审。

平台附加实际审核员、模型、指令版本、调用 ID、输入与指令哈希等可信来源。每次结构修复单独调用、计费并记录来源。旧报告及历史意见继续进入既有的人工处理和去重流程，新增核对标记不更改原去重判据。

## 管理员失败现场

JSON 结构、逐条语义或摘录核对失败时，平台在本地审核调试目录保存原始模型输出与逐项校验错误，包含调用 ID、项目/任务 ID、审核员、指令版本、创建及到期时间。错误记录给出条目/字段路径与错误类型；模型 Key 在写入前脱敏。调试目录由 `Settings.review_debug_dir` 配置，默认 `storage_dir/review-debug`；真实验收覆盖为 `platform/.verification/M3-16-review-debug`，仍由同一存储执行 30 天保留与清理，不复制原始输出到普通验收证据。调试文件与用量元数据、项目报告和项目导出分开存储，原始响应不进入项目导出。

只有通过人类登录会话认证的平台管理员可以读取以下接口，项目负责人或成员身份不增加权限，智能体 Bearer/MCP 通道无此权限：

| 接口 | 内容 |
|---|---|
| `GET /api/admin/review-debug?limit=100` | 调试记录元信息列表，不返回原始输出或错误细项；`limit` 为 1–200 |
| `GET /api/admin/review-debug/{call_id}` | 单条原始输出、逐项错误及元信息；不存在或过期返回 404 |

响应使用 `Cache-Control: no-store`。调试目录权限为 0700，记录文件为 0600；不跟随记录符号链接。记录保留 30 天，到期不可读取，由后台及读写时清理；保留期不是永久审计存档。存储失败时不能将未完成审核改写为通过。

真实验收执行方式、¥10 跨进程聚合预算及防重复 marker 见 [M3_ACCEPTANCE.md](M3_ACCEPTANCE.md)。自动化测试始终使用模型替身，真实 Key 仅由发起人写入未跟踪的 `platform/.env`。
