# 一条命令启动演示项目

在 platform 独立仓库根目录运行；主机只需 Python 3.9+、Docker Engine 和 Compose v2 插件（应用的 Python 3.12 在镜像里）。Docker 安装见[生产部署指南](DEPLOY.md)。首次构建需要访问镜像和依赖仓库，生成演示数据及浏览流程不调用外部模型或文献 API。

```sh
python3 deploy/demo.py
```

脚本完成构建、启动独立 PostgreSQL、迁移、生成样本并启动 web/worker；成功后打印 `http://127.0.0.1:18005`。只绑定本机，不要用这些公开演示账号部署公网服务。默认端口占用时用 `python3 deploy/demo.py --port 18006`，以后继续使用相同端口。已有同版本演示镜像时可加 `--no-build`，首次运行不要使用它。构建或初始化失败会返回非零，不会打印“已就绪”。

| 身份 | 用户名 | 演示密码 |
|---|---|---|
| 项目负责人，负责统稿 | demo-leader | TeamsDemo-Only-2026 |
| 组员，负责文献与概念 | demo-writer | TeamsDemo-Only-2026 |
| 组员，负责模拟数据分析 | demo-analyst | TeamsDemo-Only-2026 |

所有人物、研究问题和数据都是虚构的。项目名称、文稿、交接说明、意见来源均标明演示；预置模型意见的 `model` 为 `demo-fixed-response`，不是真实 DeepSeek 结果，也没有对应的付费调用或用量。格式检查实际读取原文件，Markdown字体检查仍按现有规则显示未覆盖。

## 给老师和同学演示的顺序

1. 用负责人登录，打开“科研交接演示（虚构数据／固定响应审核）”。方案包含3个术语、2条数据口径、3个有依赖的模块；规范涵盖4个类别并保留GB/T 7714预设。范例库和模板仍可下载。看板会标红超期未提交的统稿模块及未回应的超时协作需求，点击进入对应内容。
2. 打开“文献与概念”的交付历史：v1有两条重要意见并退回，作者采纳术语修订、不采纳“移除演示提示”的规范意见并说明场景不适用；v2改了术语，历史不采纳项关联保留，由负责人逐条裁定后采用。文件和版本绑定都能查看，旧版仍可下载。AI意见与人的选择分开记录，采用仅表示这次演示中的人类决定。
3. 切换到 demo-writer，查看本人标注与需求历史：有一条已闭环、一条已有回应待发起人确认、一条超时待回应的需求，可以演示“接手→回应→发起人确认”。建议用不同浏览器配置/隐私窗口保持各账号会话，避免误以为切换身份会保留同一会话。
4. 切换到 demo-analyst，“模拟数据分析”有一份待负责人终审的交付和一份仅本人可见的智能体稿。预置助手的令牌不输出并已吊销；历史进度及上传事件仍标明“智能体代表谁”。若要连接自己的智能体，在“我的智能体”中另行登记并只保存新显示一次的令牌。负责人账号不能看到这份待本人确认稿。
5. 切回负责人，可对模拟分析作终审，或查看活动流、任务/项目时间线和导出事件日志。可以手动触发完整衔接或方案自检来展示入口及失败提示；**真实模型关闭时没有AI结论，不会当作通过**。

预置报告由CLI初始化阶段的固定响应生成，正常web/worker没有接入演示替身。现场新上传、确认提交或重试会走正常流水线，因为真实调用关闭而保持未完成/部分失败；不会为展示效果自动给出通过。真实模型验证仍按验收计划单独执行，不能把此演示当作真实模型验收。

## 隔离、重复运行与停止

固定Compose项目名为 `teams-platform-demo`，数据库名为 `teams_demo`，角色为 `teams_demo`；命名卷为该项目的 `postgres_demo_data` 和 `files_demo_data`。独立镜像标签 `teams-platform:demo`，不覆盖开发/生产镜像。脚本显式使用 `--env-file /dev/null`（Windows不支持此Linux/macOS脚本），清除继承的应用/模型/数据库变量；Key强制为空、live强制false，管理员为空。不会读取用户 `.env`、连接正式库或共享开发文件卷。演示库本身不含真实数据，不要把正式数据导入这些卷。

重复运行会先停止演示web/worker，再校验数据库完成事件与文件卷标记配对、所有数据库记录引用文件的大小和SHA-256；匹配后保留现场，不再建账号、追加版本或覆盖课堂上的修改。账户密码也不会被重设。并发启动命令使用宿主锁，初始化另有数据库事务锁和文件卷锁。生成过程中的服务提交被包在同一个外部数据库事务里，失败整体回滚，不会留下半套已提交账号和交付。失败的文件卷会保留“未完成”标记并拒绝冒充完整演示；数据库已提交、只差完成标记的情况，在配对和文件校验通过后可继续完成标记。

```sh
python3 deploy/demo.py --stop
```

只停止演示服务，保留卷。不要为重新演示而删除开发或生产卷。需要全新演示时，优先在另一台机器或隔离Docker环境运行同一命令；本脚本不提供清空现有数据的开关。初始化失败、标记不匹配、文件缺失或旧版本迁移问题时先保留现场，检查以下命令，不要通过手工写完成标记来掩盖失败：

```sh
docker compose --env-file /dev/null -p teams-platform-demo -f deploy/compose.demo.yaml ps -a
docker compose --env-file /dev/null -p teams-platform-demo -f deploy/compose.demo.yaml logs --tail=80 postgres web worker
```

原始初始化错误只输出安全的通用信息，避免数据库异常回显凭据；运行前确认使用本指南的固定演示环境。`demo_bootstrap` CLI只接受显式 `DEMO_DATABASE_URL`（无额外URL参数的PostgreSQL `teams_demo` 库）和绝对路径 `DEMO_STORAGE_DIR`，不读取默认应用库；不建议绕过启动脚本直接对自行拼接的目标执行。

在内存有限的开发机上演示前停止其他验证环境，不并行跑全量数据库测试和镜像构建；结束后停止演示，按原配置恢复验证环境。正式服务器上的日常运维按[部署指南](DEPLOY.md)执行，演示账号不能用于正式使用。
