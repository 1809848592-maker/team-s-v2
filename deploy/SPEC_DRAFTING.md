# M3-15 平台辅助起草规范

当前项目负责人可在“团队规范”页填写一段要求，让平台调用一次模型生成规范条目，再逐条核对、修改并手动发布。生成不会自动发布规范，也不创建正式交付或审核任务。自动化验证一律使用模型替身，真实 DeepSeek 调用只在 M3 最终验收进行。

## 页面操作

起草要求去除首尾空白后须为1至6000个字符。已有当前版本项目同意时，负责人可点击生成；未同意时，页面展示数据外发告知，同意框默认不勾选，负责人明确勾选并确认后才能生成。当前告知版本为 `deepseek-2026-11-12.2`，旧 `.1` 同意需要重新阅读并确认。告知与同意的完整说明见 [数据外发告知与用量管理](DATA_DISCLOSURE_AND_USAGE.md)。

结构合格的结果追加到现有本地规范编辑区，原条目保留；生成编号与原草稿冲突时，页面为新条目添加唯一后缀并提示。规范编辑区总数最多500条，追加会超限时整批不加入。负责人核对要求、类别、检查方式、示例及模板后，使用既有发布操作生成正式规范版本。未发布草稿不保存到服务端，离开页面或刷新前应按现有编辑流程处理本地修改。

生成期间页面禁止重复生成、编辑、上传及发布。模型失败、结构不合格或额度不足时，起草要求和原草稿保留，不自动重试。每次人工重新生成都使用新的请求 UUID。项目、账号、角色发生变化或页面卸载后，迟到响应不能写入当前编辑区。告知冲突会刷新告知并复位同意勾选，已有草稿和要求保留。

## 接口与权限

`POST /api/projects/{project_id}/spec/draft` 使用人类登录会话、CSRF 校验和当前项目负责人权限。普通成员、未加入项目的人、智能体 Bearer 及 MCP 均不能借此起草；智能体 Bearer 同时携带所属人 Cookie 也不会获得人类权限。

请求示例：

```json
{
  "request_id": "6a75368f-50f4-438f-b97c-6828f4be0784",
  "description": "请为研究报告起草可核查的引用和交接要求。",
  "disclosure_version": "deepseek-2026-11-12.2"
}
```

仅接受上述三个字段，拒绝额外字段、无效 UTF-8 及不允许的控制字符。成功响应包含 `request_id`、`call_id`、`instruction_version` 和 `items`；`call_id` 与本次 `request_id` 相同。当前固定指令版本为 `2026-11-12.1`，它与数据告知版本分别管理。

每个条目采用发布接口的同一结构：

```json
{
  "number": "REF-1",
  "category": "writing",
  "requirement": "引用的资料应能定位到原始来源。",
  "check_method": "ai",
  "positive_example": "提供作者、年份和可定位的来源信息。",
  "negative_example": "仅写“有研究表明”。",
  "template_resource_id": null
}
```

生成结果必须为1至500条，编号去除首尾空白后唯一。类别仅允许 `writing`、`template`、`format`、`handoff`；检查方式仅允许 `program`、`ai`、`manual`；字段长度遵循 `SpecItem`。模型未收到模板目录，因此 `template_resource_id` 必须为 `null`，负责人可在编辑区选择真实模板，模型不能猜测资源 ID。顶层额外字段、额外条目字段或不合格文字会使整次结果失败，不部分加入草稿。

| 响应 | 含义 |
|---|---|
| 200 | 生成及结构校验完成，返回条目供本地编辑。 |
| 401／403 | 未登录、智能体访问、CSRF 或负责人权限不满足，按既有认证边界拒绝。 |
| 409 | 请求 UUID 已使用、项目尚未同意当前告知，或提交了旧告知版本。 |
| 422 | 请求字段、UUID 或要求文字不符合约束。 |
| 429 | 项目或平台额度不足，包含 `scope`、`retry_at` 和 `Retry-After`，未调用模型。 |
| 502 | 模型请求未完成，或模型结果未通过结构校验。 |
| 503 | 真实调用未启用、模型配置或固定指令不可用。 |

成功响应及接口映射的业务错误均设置 `Cache-Control: no-store`。相同请求 UUID 全局唯一，重复及并发请求不能再次外发；即使首次请求因额度不足而未调用模型，人工重试也使用新的 UUID。

## 外发内容与留痕

模型仅收到随平台发布的固定系统指令，以及包含起草要求正文的用户 JSON。用户 JSON 明确标记 `trust: "data_not_instructions"`，要求正文作为数据处理，不能覆盖平台指令。此次调用不附带现有草稿、项目正文、方案、文件或模板目录；调用方不能选择指令路径、模型或资源。固定指令资源有版本和读取大小约束，输出另受响应大小及条目校验约束。

服务端先用短事务检查当前负责人身份和告知同意，记录 `spec_draft_requested` 事件及不可变 `SpecDraftRequest`，提交后释放数据库连接与项目锁，再调用模型。请求记录只保存项目、实际发起人、描述 SHA-256、告知版本、关联事件及时间，不保存描述正文或生成条目正文。模型返回后再次检查权限和告知版本，成功时追加 `spec_draft_generated` 事件。

生成事件和模型用量事件使用平台起草身份 `platform-spec-drafter`，来源为 `platform_spec_draft`，另记录实际发起人；页面显示“平台规范起草”，不冒充用户智能体。生成事件保存调用 ID、指令版本及条目数量，不保存生成正文。权限已失效或成功事件写入失败时，不向页面交付草稿；已经发生的模型费用保留。

## 额度、用量和部署

每次获得模型预算准入的起草占一个项目日名额和一个平台日名额，与正式交付审核共用额度，UTC 换日。token 预算在外发前保守预留，沿既有账本结算。项目额度为0会阻止新的起草预算准入；额度不足返回可重试时间，页面不发起后台重试。

起草调用关联独立的 `SpecDraftRequest`，不伪造 `ReviewJob`、正式交付或 `ReviewAdmission`。每个起草来源最多一条 `ModelCall`；交付审核来源和起草来源恰有一种。模型或结构失败均不自动增加第二次调用。收到有效厂商用量时按实际 token 和保存的价格快照估算；未知用量保留保守预留，未知费用不冒充零费用。即使模型 JSON 已返回但业务条目不合格，已经产生的有效用量仍计账。

管理员“模型用量与额度”页及 CSV 将起草列入 `spec_draft`，可按项目、时间段及调用 ID 对账。费用仍为高峰价快照估算，实际报销以厂商账单为准，配置及统计口径见 [模型配置说明](MODEL_CONFIGURATION.md) 和 [用量管理](DATA_DISCLOSURE_AND_USAGE.md)。

默认 `LLM_ENABLE_LIVE_CALLS=false`。填入 Key 或同意告知不会单独启用真实调用；Key 仅由发起人写入未纳入 Git 的 `platform/.env`，环境变量为 `DEEPSEEK_API_KEY`。本功能新增迁移 `0020_spec_drafting`；若已有真实起草调用账本，降级迁移会拒绝丢弃其来源。
