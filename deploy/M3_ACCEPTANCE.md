# M3 审核全流程验收

从 `platform/backend/` 运行 `../scripts/accept_m3.py`。它启动随机回环端口的真实 HTTP 服务，以人类会话创建合成账号、项目、方案、规范及当前版本知情同意，再经正式交付接口、持久队列领取、四阶段 `execute_pipeline` 和 `complete_job` 完成审核。没有导入测试 fixture，没有启动会忽略 schema override 的默认 worker，也没有改写审核结论。

每轮在明确指定的本地 PostgreSQL 测试数据库里创建随机 `accept_m3_*` schema，并使用独立临时存储。数据库名称必须含 `test`、`smoke` 或 `accept`，拒绝 URL 查询参数及非本地地址。结束时停止本轮 HTTP 服务、删除本轮 schema 和临时存储，独立复查清理结果；失败也保留 JSON 证据。它不会修改或停止其他环境。

## 默认替身验证

```sh
cd /absolute/path/to/Team.s/platform/backend
TEST_DATABASE_URL=postgresql+psycopg://teams_test:teams_test_only@127.0.0.1:15432/teams_m1_test \
  .venv/bin/python ../scripts/accept_m3.py \
  --database-url postgresql+psycopg://teams_test:teams_test_only@127.0.0.1:15432/teams_m1_test
```

默认 `--mode mock`。模型使用真实 `LLMClient`、原有模型配置、来源和用量账本，只有传输使用 `httpx2.MockTransport`；公开文献接口也使用固定传输替身。不会读取任何 `.env` 或 Key 文件，不访问外部模型和文献服务。模型替身仍经过完整输出结构及原文证据校验，程序字体检查没有替换。

## 最终真实模型验收

仅在发起人已授权的 M3 最终验收中运行：

```sh
cd /absolute/path/to/Team.s/platform/backend
TEST_DATABASE_URL=postgresql+psycopg://teams_test:teams_test_only@127.0.0.1:15432/teams_m1_test \
  .venv/bin/python ../scripts/accept_m3.py \
  --mode live \
  --database-url postgresql+psycopg://teams_test:teams_test_only@127.0.0.1:15432/teams_m1_test \
  --key-file /absolute/path/to/Team.s/platform/.env
```

只有显式 `live` 及绝对 `--key-file` 才读取真实 Key；路径必须是本项目 `platform/.env`。仅提取一条字面量 `DEEPSEEK_API_KEY` 赋值，不执行文件、不展开变量、不使用其余设置。Key 只传给模型客户端的 `SecretStr`，不会输出或写入证据。应用 HTTP 服务自身仍关闭真实调用；驱动构造的审核客户端显式开启。真实 transport 只允许 `POST https://api.deepseek.com/chat/completions`，禁止跟随重定向，关闭环境代理；Key 不会发送给 Crossref 或 OpenAlex。

真实模式使用真实 DeepSeek 和真实 `CitationDatabaseClient`。模型未识别预期问题、文献接口未能核验、输出结构或证据校验失败、超时、额度不足等情况均返回非零并保留实际结果，不补造意见或宣称通过。参考文献是随机标题的虚构英文条目；只有两库查询成功且均无匹配才算文献阻断。任何网络/限流问题产生的“未能核验”不替代这一验收要求。

合成英文文献使用 `Zqxv` 加本轮随机标识组成的单词标题，章节标题使用 `References`，避免通用英文检索词产生过多候选，也避免抽取原文包含中文章节名而触发保守中文文献分类。在第一次模型调用前，驱动先通过真实 `CitationDatabaseClient` 核对该标题、作者和年份；两库都明确 `no_match` 才继续，并保存 `fixture-verification.json`。预核验失败时模型调用为零；替身模式也经过同一客户端和固定数据库传输。这只选择验收材料，没有改变产品的保守核验规则。

## 检查内容与开销边界

1. 生成故意在首段使用错误字体、包含虚构英文参考文献、术语定义冲突及无实证依据因果论断的 DOCX。其余段落与文档默认样式使用正确字体，避免重复格式问题膨胀历史；首段字体仍必须由真实程序检查产生阻断。四类问题须分别由真实程序/审核流水线发现，首稿退回。
2. 以真实 HTTP 逐条标注：修复项采纳，逻辑意见不采纳并写理由，全部旧意见均须处理，至少展示两条采纳和一条不采纳。生成修订 DOCX，恢复字体和术语、删除虚构文献；逻辑段落保留原待检验命题片段和原段落位置，同时明确限定为待检验/待证伪的假设，不能当作已经成立的结论。重新正式提交；不采纳历史保留且不能继续阻断，不能以循环上限绕过审核代替完成。
3. 负责人读取完整终审上下文、核对不采纳理由并终审采用修订版。
4. 在初始方案预设的独立恢复验证模块提交第三份材料，同一成员负责，使用相同概念和测量口径、正确字体及明确待检验的假设，不含旧错误断言引用、没有前两版的意见历史。本地 transport 模拟连接断开，在任何真实模型网络连接前拒绝请求，不更改系统网络或把 Key 发往本地假厂商。交付必须停在部分失败、任务失败，不能进入终审。
5. 恢复相同客户端，经提交人人类会话调用公开 `POST /api/projects/{project_id}/deliveries/{delivery_id}/review/retry`，携当前 `expected_revision`，再显式执行一次，必须完成审核并进入终审。
6. 本轮合成负责人同时配置为隔离应用的平台管理员，读取真实用量汇总及 CSV；按调用 ID、逐审核员、token、未知次数和 Decimal 费用与底层账本逐项对账，不改写用量。

两版合成正文和绑定方案讨论同一“新增一次审核是否及如何影响交接质量”问题。交接质量限定为交接材料完整性及补充沟通负担：主要结果为首次接收时实填必填字段数/冻结四项字段总数，辅助结果为同一时点的字段缺漏数及接收后24小时的缺漏追问轮次。比较统一字段清单、评价时点及观察窗；协作负荷定义为审核前一个自然日的交接任务数，只作为预定义的分层或调整背景变量。定义和验证边界同时写入方案及正文，逻辑审核实际读到的模块目标与主线也包含这些关系。

问题稿明确在没有样本、对照或实证数据时仍声称普遍因果改善；修订稿仅提出可证伪假设和候选机制，给出后续预注册及验证要点，不提供效应估计或实证结论。两版交接说明分别对应各自正文。第三段保留相同位置的旧断言原文作为待证伪对象，历史不采纳理由聚焦本模块的定义/假设职责与后续验证；这只完善验收材料，不改变审核员指令、严重度、去重阈值或实际审核结论。模型仍可指出新的重要问题，验收对此照实失败，替身通过不代表真实模型验收通过。

首稿和修订稿始终属于原模块，严格验证历史标注、去重及终审；断网/恢复属于另一模块，使用第三份明确假设稿，避免先前错误断言和历史意见影响网络恢复这一独立场景。它仍通过相同人类正式提交、持久队列、四阶段流水线及公开重试接口，不替换审核结果，也不通过增加模块改变3份审核准入及标准19次调用边界。

每次领取显式 900 秒租约/审核时限，并用进程信号设置同样的硬性期限；初始任务最多一次执行，脚本不启动自动重试循环。五个模型审核员顺序执行，单次正常流水线 5 个模型调用；每位审核员最多另有一次结构修复。断网时文献抽取未完成，引用对应审核不会调用，所以无结构重试的完整驱动为 19 次模型调用（15 次有效、4 次本地断网）。整个驱动最多 29 个模型账本调用，达到上限立即停止新调用；可用 `--max-model-calls 1..29` 下调，较低值也用于验证费用门禁。

`--model-timeout-seconds` 可显式设置本驱动五个模型审核员的 HTTP 超时，只接受 1 至 180 秒整数；例如 `--model-timeout-seconds 120`。默认不覆盖，沿用正式配置中每个审核员各自的超时（普通审核员 60 秒，逻辑与衔接 120 秒）。该参数只覆盖传给客户端的审核员超时，不修改模型名称、思考开关、输出 token 上限、价格快照或产品配置。每份审核的 900 秒总租约和信号硬期限仍生效；延长单次 HTTP 等待不会增加总期限、调用次数、token 预算或自动重试次数，超时仍按实际未完成及未知用量处理。覆盖参数（未指定为 `null`）及各审核员实际超时映射保存在 `report.json` 的 `limits` 中。

全运行默认 token 预算 300000，可用 `--token-budget` 调整为 10000 至 500000。每次调用（包括结构修复）在外发前，以当前输入 UTF-8 字节数加 1024 余量及输出上限计算保守预留，并累加本轮所有 UTC 日期、所有审核员的已结算 token 和 `reserved`/`unknown` 未释放预留；加本次预留超过上限立即停止，跨 UTC 午夜也不重置。既有平台每日额度准入继续生效。无有效用量的断网调用保留保守预算，不记为零 token 或零费用。证据分别列出已结算 token、未知调用继续占用的预留、两者合计及本轮预算是否遵守，并核对全部平台日桶与账本；如实际用量异常超过保守预留，保存实际逐调用用量后将验收标记为失败。驱动最多准入 3 份正式审核，每份调用总数也有限；没有无限付费重试。

配置继续使用 2026-11-11 高峰价格快照：三个普通审核员每次最多输出 4096 token，逻辑/衔接每次最多输出 8192（包含思考 token）。一次标准五调用的输出部分最多估算 ¥0.540672；每位均结构修复一次时为 ¥1.081344，另加实际输入费用。token 预算是资源边界，不是平台人民币余额保证；价格估算不等于真实账单。`finish_reason=length` 直接视为未完成，不能因文字看似合理而采纳。真实验收若碰到此情况应报告，不自动增大上限或反复付费。

证据默认保存在忽略的 `platform/.verification/M3-acceptance/run-*`；`--output-dir` 可指定其他目录。保留三份合成 DOCX、每轮平台结构化审核报告、最终决定、`usage.json` 和 `report.json`。账本按审核员汇总调用次数、已知 token、未知用量、已知估算费用及未知费用，费用使用 Decimal 精确相加；逐调用字段不包含 Key、请求头、endpoint 或完整厂商响应。终端仅输出步骤、汇总及证据目录。退出码 0 表示全部流程和清理都成功，1 表示流程或清理失败，2 表示命令门禁未满足。

这份驱动覆盖 API、真实四阶段与账本。浏览器中的报告布局、逐条控件、读失败重试、轮询保留表单及人类终审交互，还须按 M3-14 的 Playwright 浏览器验证独立核对。运行全量测试和浏览器后再串行构建容器；当前约 2.83 GiB Docker VM 有构建导致测试 PostgreSQL OOM 的已知限制，不能与本驱动并行构建。
