适用范围：DeepSeek 审核流水线、项目负责人知情同意、提交人首次告知及平台管理员用量与额度页面。本项开发和自动化验证不调用真实 DeepSeek；真实模型验证只在 M3 最终验收进行。本文不包含真实 Key。

## 项目告知和同意

当前告知版本为 `deepseek-2026-11-12.1`，定义在 `backend/app/services/model_disclosure.py`。告知明确说明：审核会向 DeepSeek 发送交付提取文本、相关方案和规范、意见处理历史及所需上游交付摘要；文献核查另向 Crossref、OpenAlex 发送参考文献的题名、作者、年份或 DOI。界面同时展示厂商名称、开放平台协议和隐私政策链接，以及尚未核实的训练和保留条件。

创建项目时，同意框默认不勾选。创建者可先保存项目，之后由任一当前项目负责人在任务页明确勾选并确认。普通成员、平台管理员身份以及智能体令牌都不能替代项目负责人同意；管理员本人若同时是该项目负责人，仍须使用人类会话操作。

负责人同意后保存接受人、时间、告知版本和当时告知快照，追加 `model_data_transfer_consented` 事件。同一项目、同一告知版本的重复确认幂等；记录不可修改或删除。迁移不会给既有项目自动填入同意，旧项目也必须主动阅读并选择。

项目同意与提交人告知分别记录。每位提交人在该项目、当前告知版本下首次正式提交时，必须阅读并携带当前 `disclosure_version`；本人确认智能体稿件走同一路径。告知记录与正式交付、事件在同一事务保存，失败不留下虚假的阅读记录。之后已确认的提交可省略版本，但显式提交旧版本仍被拒绝。项目负责人同意不替代提交人告知，提交人阅读也不替代负责人同意。

告知更新后，旧版本同意不再满足当前审核条件。选择同意的创建请求、负责人同意或正式提交携带陈旧版本会得到409，页面刷新告知后要求重新阅读；创建项目的同意勾选也会复位。

没有当前同意时仍可保存正式交付，但 AI 审核不能完成或外发，不能显示为通过。系统在整个审核流水线运行前以及每次模型预算预留前检查同意，即使使用模型替身也执行相同检查；没有同意时不会先消耗模型预算再拦截。此限制沿用现有审核状态，不增加新交付状态。

`LLM_ENABLE_LIVE_CALLS=false` 是另一道默认关闭的真实模型开关。填写 `DEEPSEEK_API_KEY`、负责人同意或首次提交中的任一操作，都不会单独打开真实调用。Key 只由发起人写入未纳入 Git 的 `platform/.env`，前端、告知快照、用量 CSV 和本文均不保存 Key。模型辅助起草规范属于后续 M3-15，当前 `spec_draft` 仅为预留配置。

### 告知接口

以下接口均使用人类登录会话；写操作还需既有 CSRF 校验。智能体 Bearer 即使同时携带所属人 Cookie，也不能调用负责人同意接口。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/model-disclosure` | 读取创建项目所需的当前告知。 |
| `GET /api/projects/{project_id}/model-disclosure` | 项目成员读取告知、当前同意、本人首次提交告知状态及是否有权同意。 |
| `POST /api/projects/{project_id}/model-consent` | 当前项目负责人提交 `{"disclosure_version":"deepseek-2026-11-12.1"}`。 |

创建项目的 `data_transfer_consent` 为严格布尔值、默认 `false`；选择同意时需当前告知版本。正式上传以表单字段、本人确认草稿以 JSON 字段携带 `disclosure_version`。

## 管理员入口和权限

通过部署环境变量 `PLATFORM_ADMIN_USER_IDS` 指定管理员，值为人类账号 UUID 的逗号分隔列表。该配置与项目的负责人角色独立。修改部署环境后需按部署流程重新创建使用该配置的服务容器，不能仅修改浏览器状态。

管理员登录后可从侧栏打开“模型用量与额度”，即使本人没有加入任何项目也可访问。页面可跨项目读取项目名称、调用元数据及额度；这不会授予项目正文、正式交付、待确认稿、审核内容或密钥的通用读取权限。后端独立校验管理员身份，隐藏按钮不是权限依据。未登录、非管理员和智能体令牌均被拒绝，智能体同时携带管理员本人 Cookie 也不会切换成人类权限。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/admin/usage?start=YYYY-MM-DD&end=YYYY-MM-DD` | 总计、按项目及按审核员汇总，附平台限额。 |
| `GET /api/admin/usage.csv?start=YYYY-MM-DD&end=YYYY-MM-DD` | 相同条件的逐调用明细。 |
| `GET /api/admin/projects` | 项目名称及当前每日审核额度。 |
| `PUT /api/admin/projects/{project_id}/quota` | 修改项目额度，需 CSRF；请求如 `{"daily_review_limit":0}`。 |

两种用量查询可附 `project_id` 筛选。响应均使用 `Cache-Control: no-store`。

## 统计范围和未知用量

页面默认查询最近7个 UTC 日期，包含今天。查询依据模型账本 `ModelCall.day`，首日和末日均包含在内，不能按浏览器当地日期理解。开始日期不得晚于结束日期；一次最多366天、100000条调用记录。超限返回422并要求缩小范围或筛选项目，不静默截断数据。

汇总和 CSV 包含选定范围内所有调用状态。失败调用只要收到了有效厂商用量，仍计入已知 token 和费用；预留中或未取得有效用量的调用，不会被视作测得零用量。

| 字段 | 含义 |
|---|---|
| `calls` | 范围内所有模型调用账本记录数。 |
| `measured_calls` | 已获得有效总 token 的调用数。 |
| `unknown_usage_calls` | 总 token 尚未知的调用数。 |
| `unknown_cache_calls` | 缓存命中／未命中拆分未知的调用数。 |
| `unpriced_calls` | 估算费用未知的调用数。 |
| `prompt_tokens`、`completion_tokens`、`total_tokens` | 各项已知 token 的合计。 |
| `cache_hit_tokens`、`cache_miss_tokens` | 已知缓存拆分合计。 |
| `estimated_cost_cny` | 已知人民币估算费用合计，十进制字符串，10位小数。 |

未知计数可能重叠，例如同一条调用同时缺用量、缓存和费用，不能把三个未知计数相加当作调用总数。页面的零合计只表示已知数值合计为零，须同时核对未知计数。

费用使用账本中每笔调用已保存的估算值，以 `Decimal` 精确求和，再输出10位小数。修改模型 TOML 的价格不会用新价重算旧账；缓存拆分缺失的调用保留未知费用。价格公式、快照日期和高峰价估算口径见 [模型配置说明](MODEL_CONFIGURATION.md)。报销实付金额以 DeepSeek 平台账单为准。

### CSV 对账

在页面选择日期／项目后点“导出 CSV 明细”，导出条件与查询一致。浏览器读取失败会显示错误。文件为带 UTF-8 BOM 的 CSV，每笔调用一行，列依次为：

```text
date_utc,project_id,project_name,reviewer,model,status,prompt_tokens,completion_tokens,total_tokens,cache_hit_tokens,cache_miss_tokens,estimated_cost_cny,call_id
```

未知 token、缓存拆分和费用留空，保留与数值0的区别；费用按账本输出10位小数。项目名等可能被电子表格当作公式的字段会加单引号转义。对账时，CSV 行数对应 `calls`，非空总 token 行数对应 `measured_calls`，非空数值之和应与同筛选条件的汇总一致；费用使用十进制相加。两次查询之间若有调用继续结算，需在相同账本状态下比较。

## 调整额度

项目每日审核额度允许 `0..2147483647` 的严格整数，不能使用布尔值、浮点数或数字字符串。设为0只阻止新的审核名额（`ReviewAdmission`）准入；已经获得名额的同份审核仍可继续，并继续受到平台 token 总量及单份调用次数限制。它不是取消在途审核，也不清空当天已用额度或修改历史模型账本。

同额度重复保存不追加事件；实际修改追加 `llm_project_quota_updated`，记录旧值、新值和真实操作人，额度与事件同事务提交，失败一起回滚。

平台限额在页面只读，由部署环境控制：

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `LLM_PROJECT_DAILY_REVIEWS` | 20 | 尚未单独配置的项目每日审核名额。 |
| `LLM_PLATFORM_DAILY_REVIEWS` | 200 | 平台每日审核名额总上限。 |
| `LLM_PLATFORM_DAILY_TOKENS` | 1000000 | 平台每日 token 预算总上限。 |
| `LLM_MAX_CALLS_PER_REVIEW` | 64 | 同份审核允许的模型调用总数上限。 |

每日额度按 UTC 日界线计算，以一份正式交付审核任务为单位，不能按每名审核员重复扣审核名额。日额度不足时暂停审核并提示可再尝试时间，不判通过；单份调用总数上限是防循环的确定性失败限制，不能靠换天重置。管理员提高项目额度仍需遵守平台上限及数据外发同意条件。
